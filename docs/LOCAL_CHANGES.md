## Реализация Silero

`SileroTTSManager` больше не создаёт отдельные экземпляры `v5_ru` для основного голоса и комментатора. Используется один объект `SileroTTS`; перед каждым последовательным синтезом вызывается `change_speaker()`. В установленной библиотеке этот метод только проверяет и присваивает speaker, не вызывая `init_model()` и не перезагружая веса.

Неиспользуемый `_model_instance` удалён. Глобальный singleton не вводился: модели принадлежат конкретному экземпляру менеджера, а раздельные `asyncio.Lock` защищают ленивую инициализацию RU и EN.

### CUDA и CPU

Устройство выбирается один раз при первой фактической загрузке модели:

```python
"cuda" if torch.cuda.is_available() else "cpu"
```

Выбранное значение передаётся в конструктор `SileroTTS` и записывается в лог как `Silero: выбрано устройство ...`. CPU остаётся автоматическим fallback. CUDA-синтез в среде Codex не проверялся, поскольку там `torch.cuda.is_available()` возвращал `False`.

### Lazy loading моделей

- `v5_ru` загружается при первом непустом сегменте, маршрутизированном как русский.
- `v3_en` не загружается во время общей инициализации или для русской книги. Она создаётся только при первом сегменте с латинскими буквами и без кириллицы.
- Ошибка первой инициализации `v3_en` запоминается на время жизни менеджера; последующие английские сегменты получают тишину без повторных попыток загрузки.

### Маршрутизация текста

- Есть хотя бы одна кириллическая буква → весь сегмент синтезирует `v5_ru`.
- Кириллицы нет, но есть латинская буква `A-Z`/`a-z` → лениво используется `v3_en`.
- Нет букв, присутствуют только цифры, пробелы или знаки → используется `v5_ru`.
- Смешанный русско-английский сегмент не разбивается: наличие кириллицы имеет приоритет, поэтому весь сегмент остаётся на `v5_ru`.

## Установка и запуск

Требуются Python 3.11+, `ffmpeg` и зависимости Silero:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -e .
pip install -e .[silero]
python main.py
```

Для CUDA перед установкой Silero следует установить совместимую с системой CUDA-сборку PyTorch. Проверка перед запуском:

```bash
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

Альтернативный запуск существующего окружения проекта: `make run`.

## Известные ограничения и проверка первой полной книги

- Полноценного разбиения смешанного русского/английского текста нет.
- Английский `en_0` выбран как поддерживаемый speaker, но качество и соответствие полу голоса отдельно не оценивались.
- Один объект RU-модели и изменяемый speaker рассчитаны на текущий последовательный синтез; параллельный вызов одного менеджера не тестировался.
- После реальной загрузки EN обе модели остаются в памяти менеджера; на GPU с 4 ГБ VRAM нужно проверить потребление памяти.
- README исходного проекта всё ещё может содержать старые сведения `lj_16khz` и описание Silero как CPU-only; это документационное расхождение не исправлялось в рамках точечной доработки.

На первой полной русской книге следует проверить:

1. В логе выбрано `cuda`, а `nvidia-smi` показывает загрузку RTX 3050 во время синтеза.
2. `v5_ru` загружается один раз на запуск, `v3_en` не загружается при отсутствии латинских сегментов.
3. Основной голос и комментатор действительно чередуются без повторной загрузки модели.
4. Нет CUDA OOM, деградации скорости или роста памяти на длинных главах.
5. Цифровые заголовки, знаки, имена на латинице и смешанные фразы дают приемлемый звук.
6. Итоговая книга сохраняет правильный порядок сегментов, паузы и непустое аудио во всех главах.
